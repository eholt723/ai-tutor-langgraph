This demo showcases the difference between the unmodified TinyLlama-1.1B model and a custom LoRA-finetuned variant designed specifically for tutoring. The base model shows how a small LLM behaves with no guidance — answers may drift, vary in quality, or run long. The fine-tuned tutor model adds structure, clarity, and a consistent teaching style aimed at beginners.

Because this is a 1.1B-parameter model, even with careful prompting and fine-tuning it can still behave like a "tiny" model: occasional inaccuracies, repetition, or uneven depth are expected. This demo is meant to show how much LoRA can improve consistency, not to claim perfect results.

Phase 1 is what you're seeing here: a minimal, end-to-end AI tutor running inside a single Docker container on Hugging Face Spaces, using a quantized GGUF build for efficient CPU inference.

Phase 2 is a LangGraph-powered tutoring pipeline with multi-step reasoning, Retrieval-Augmented Generation (RAG) over curated course materials, a feedback-driven refinement loop, and expanded evaluation tooling. The goal is a more interactive, context-aware system that goes beyond single-shot answers and supports real learning progression.

What is this?

An AI tutoring assistant that shows the measurable difference LoRA fine-tuning makes on a small language model. Ask the same programming question to both models and see how training transforms structure, clarity, and teaching quality — using the same 1.1B-parameter base. Built end-to-end: dataset curation, QLoRA fine-tuning, GGUF quantization, FastAPI backend, Docker deployment.

How It Works

1
Question submitted User types a programming question in the GitHub Pages frontend and selects base or fine-tuned mode.
2
Backend receives request FastAPI on Hugging Face Spaces handles the POST /chat call. On first startup, the container pulls GGUF model files from HF Hub.
3
Input normalization Contractions are expanded, capitalization is applied, and a trailing question mark is enforced — keeping input close to the training distribution.
4
llama.cpp inference Base mode: raw TinyLlama-1.1B GGUF completion. Fine-tuned mode: same base with a LoRA adapter applied, producing structured 3-part tutor answers.
5
Answer returned Fine-tuned answers are post-processed into Core Idea / Step-by-Step Example / Common Mistake format. Base answers are returned as-is.

What Was Built

  • ✓QLoRA fine-tuning pipeline on a custom CEIS150 introductory programming dataset
  • ✓GGUF quantization (4-bit) + LoRA adapter in GGUF format, served via llama.cpp on CPU
  • ✓FastAPI backend: input validation, health endpoint, prompt debug mode, CORS for two origins
  • ✓Dockerized deployment to Hugging Face Spaces — models downloaded from HF Hub at startup, not baked into the image
  • ✓RAG vector store using sentence-transformers and cosine similarity — no FAISS dependency
  • ✓LangGraph multi-step pipeline: config → data → model → evaluate → RAG index → chat
  • ✓128 tests: unit, parametrized, fixture-based integration, CORS origin allow/deny coverage
  • ✓Responsive frontend with dark/light mode, mobile intro overlay, live backend health indicator
